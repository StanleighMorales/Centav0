# v0.0.4 Improvements Design

Branch: `feature/v0.0.4-improvements` (off `develop`, SDK 54 per AGENTS.md)

## 1. Account-to-account transfers

**Data model**
- Add `'Transfer'` to `TransactionType` (`src/domain/types.ts`), currently `'Expense' | 'Income'`.
- Add `toAccountId?: string` to `Transaction`, used only when `type === 'Transfer'`. `accountId` continues to mean the source account.
- Any account type (Cash/Bank/EWallet/CreditCard/Other) can be source or destination.

**Repository**
- `SqliteTransactionRepository.createTransfer(input)`: within one `db.withTransactionAsync`, debit `accountId.currentBalance`, credit `toAccountId.currentBalance`, insert one `Transfer`-type row (no `categoryId`).
- Validation: block the transfer if it would take a non-CreditCard source account negative (same rule debt payments already enforce). CreditCard sources are exempt and can go negative.
- `update()`/`softDelete()` on a transfer row must reverse both legs (debit reversed on dest, credit reversed on source), mirroring the existing reversal logic for Expense/Income.

**UI**
- New `src/components/transactions/TransferSheet.tsx` (modeled on `AddTransactionSheet.tsx`): source account picker, destination account picker (excludes source from the list), amount, optional note.
- Entry point: alongside the existing add-transaction action (dashboard/transactions tab).
- `TransactionRow.tsx`: transfer rows render "SourceName → DestName" in place of the category label (transfers have no category).

**Reports/Dashboard impact**
- All income/expense aggregation (`delta()`, Reports summary, Dashboard stats) explicitly excludes `type === 'Transfer'` — transfers move money between accounts but are not P&L events.

## 2. Debt paid display + monthly total

**Fully-paid display**
- Debt list card and debt detail screen (`app/debts/[id].tsx`): when `debt.status === 'Paid'` (outstandingBalance === 0), replace the "$0.00 remaining" number with "Fully Paid • $X total paid".
- Total paid = sum of `amount` across that debt's non-deleted rows in `debt_payments` (existing `debtPaymentRepo.listByDebt`).

**Monthly paid summary**
- Debts list screen gets a summary header: "Paid this month: $X".
- Computed client-side: `debtPaymentRepo.list({ from: startOfMonth, to: endOfMonth })`, sum `amount` — same query pattern Reports already uses for its own date-ranged sums. No new repository method needed.

## 3. Reports layout fix

- `app/reports/index.tsx`, `summaryCard` (~line 207-222): change the row of 3 columns (`flexDirection: 'row'`, divided by vertical `summaryDivider`) into a column of 3 full-width rows, each with label left / value right, divided by horizontal dividers.
- Each row's value `Text` gets `numberOfLines={1}` and `ellipsizeMode="tail"` so an oversized number truncates with "…" instead of wrapping to a second line.
- Because each row now spans the full card width, the value has much more horizontal room before truncation ever triggers.

## 4. Dashboard recent transactions filter

- `app/(tabs)/index.tsx`: add a small Day/Week chip pair above the existing "Recent" `SectionHeader`.
- Filters `recentTxns` by `date` (today vs. last 7 days) client-side, before the existing slice-to-5, using the same chip visual pattern as the payment-mode chips in `AddPaymentSheet.tsx`.

## 5. Transactions tab filter + expand

**Filter**
- `app/(tabs)/transactions.tsx`: add a Day/Week/Month/Year/All chip row above the `SectionList`.
- Filters the transaction list by `date` range client-side before grouping into sections (matches how the existing `SectionList` grouping already works).

**Expand / detail**
- Tapping a `TransactionRow` opens a new `src/components/transactions/TransactionDetailSheet.tsx` bottom sheet.
- Shows: attached image (`receiptUri`, if present), full note, category, account, exact timestamp.
- Transfer-type transactions show source/destination accounts instead of category.

## Out of scope
- No double-entry ledger / audit trail beyond the single Transfer transaction row.
- No recurring/scheduled transfers.
- No changes to CreditCard bill/due-date logic.
