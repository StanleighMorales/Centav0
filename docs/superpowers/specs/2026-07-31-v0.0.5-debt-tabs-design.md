# v0.0.5: Debt Type Tabs + Auto Loan Disbursement

## Problem

The Debts screen currently lists all debts in one flat list, filtered only by
status (Open/Overdue/Paid). Users can't separate credit-card-style
obligations from bank loans from ad-hoc debts. Additionally, when a user
takes out a Loan, the borrowed money isn't reflected anywhere in their
accounts — they have to manually add an income/transfer to make it spendable.

## Goals

- Split the Debts screen into three top-level tabs: **Credit**, **Loan**,
  **Custom**. Each still supports the existing Open/Overdue/Paid filter.
- When a **Loan** debt is created, automatically credit a chosen account with
  the loan amount so it's immediately usable.

## Non-goals

- No changes to Lending (money owed *to* the user by other people) — that
  stays a separate feature.
- No per-type field differences beyond the Loan disbursement account picker.
  Credit and Custom use the exact form that exists today.
- No retroactive reclassification UI — existing debts silently become
  `Custom`; users can edit them into another tab if they want.

## Data model changes

`Debt` gains two fields:

```ts
export type DebtType = 'Credit' | 'Loan' | 'Custom';

export interface Debt extends AuditFields, LocalSyncFields {
  // ...existing fields...
  debtType: DebtType;
  /** Account credited with originalAmount at creation. Loan debts only. */
  disbursementAccountId: string | null;
}
```

`CreateDebtInput` gains:

```ts
export interface CreateDebtInput {
  // ...existing fields...
  debtType: DebtType;
  /** Required when debtType === 'Loan'. Account to credit with originalAmount. */
  accountId?: string;
}
```

`UpdateDebtInput` is unchanged — `debtType` and `disbursementAccountId` are
fixed at creation, same as `originalAmount` already is.

## Migration

`009_debt_type` (follows the pattern in `src/db/migrations.ts`):

```sql
ALTER TABLE debts ADD COLUMN debtType TEXT NOT NULL DEFAULT 'Custom';
ALTER TABLE debts ADD COLUMN disbursementAccountId TEXT;
```

Existing rows default to `'Custom'`. No backfill logic needed beyond the
column default.

## Repository changes

**`SqliteDebtRepository.create`**
- Insert now includes `debtType` and `disbursementAccountId`.
- Wrapped in `db.withTransactionAsync`: insert the debt row, then — only if
  `debtType === 'Loan'` — credit `accounts.currentBalance` by
  `originalAmount` for `input.accountId`, and store that id as
  `disbursementAccountId` on the debt row. Mirrors how
  `SqliteDebtPaymentRepository.create` debits an account directly (no
  separate `Transaction` row is created for this movement).

**`SqliteDebtRepository.softDelete`**
- Wrapped in `db.withTransactionAsync`: mark the debt deleted, then — only if
  `disbursementAccountId` is set — subtract `originalAmount` back out of
  that account's `currentBalance`. Mirrors
  `SqliteDebtPaymentRepository.softDelete`'s balance-restore behavior.

**`IDebtRepository.create`** signature takes the extended `CreateDebtInput`.

## UI changes

**`app/(tabs)/debts.tsx`**
- Top-level tab row: `Credit | Loan | Custom` (replaces current
  Open/Overdue/Paid row).
- Secondary filter row below it: `Open | Overdue | Paid`, scoped to the
  active debtType tab (`debts.filter(d => d.debtType === activeType && d.status === activeStatus)`).
- Summary card (Total Debt / Cash+EWallets / Paid This Month) computed only
  over debts in the active debtType tab.
- FAB creates a debt with `debtType` set to whatever tab is currently active
  — the Add Debt form does not need its own type picker.

**`src/components/debts/AddDebtSheet.tsx`**
- Accepts a `debtType: DebtType` prop (passed from the active tab).
- When `debtType === 'Loan'`: render an additional required `Select` for
  "Disburse to Account" (same account list pattern as `AddPaymentSheet`,
  minus the Accumulated Balance option — disbursement targets one real
  account). Validation: required, error `'Select an account to receive the loan'`.
- On save, passes `debtType` and (for Loan) `accountId` into
  `debtRepo.create`.
- Edit mode: disbursement account is not editable (fixed at creation, greyed
  info line only: "Disbursed to {accountName}" if present).

## Open questions / risks

None outstanding — all decisions confirmed during brainstorming:
- New debtType field on existing `Debt` table (not separate tables per type).
- Loan creation credits a user-picked existing account directly (balance
  update, not a Transaction row) — consistent with existing DebtPayment
  pattern.
- Existing debts default to `Custom`.
- Deleting a Loan debt reverses the account credit.
